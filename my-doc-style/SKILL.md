# 按我的风格写文档

动笔前用 Read 工具读一遍 [references/sample.md](references/sample.md)——目标风格的完整样例，约 600 字讲完账号、开发、任务定义三件事。篇幅由读者跑通需要的步骤数决定，密度对齐样例。

一篇文档只为让读者**跑通**：先回答读者是谁、读完要做成什么事，答案决定全文取舍。

## 完成检验

逐句问：删掉这句，读者会卡在哪一步？答不上来就删。全文每一句都过了这条检验才算写完。

优先删的东西：

- 背景铺垫、原理介绍、术语表——术语在第一次出现的地方用一句话就地定义（「开发机是一台可 SSH 上去的云上开发环境」）
- 总结、FAQ、验收清单、结尾客套——最后一个知识点就是结尾
- 完整示例代码——只留读者要敲的命令，能一行就一行
- 官方文档的搬运——给一个入口链接，正文只写验证过的结论

## 结构

- `#` 标题是名词短语（「XX 测试指引」）→ 一两行背景带上入口链接 → 直接进第一个 `##`
- `##` 按读者的操作阶段切分（账号与资源 → 算子开发 → 任务定义），标题不带数字编号
- 并列方案命名为 `### 方式一：xxx`、`### 方式二：xxx`
- 一段一两句话，块与块之间空行

## 句式

- 选型对比用 bullet + 冒号，一行一个：「Python：直接跑脚本，轻量处理、单机逻辑优先走这个」
- 条件分流写成「如果是 A，那么使用 B」
- 建议自带理由：「建议把依赖都打进镜像，避免运行任务实例时重复拉取」
- 抽象规则后面跟一个具体例子：「例如代码用 `WORKERS` 控制核数、控制台选了 4 核，就要手动把 `WORKERS` 配成 4」
- 语气平直的陈述句，不用感叹号；一句话自成一段时句末不加句号，段内多句才用句号分隔

## 标记

- 关键约束**加粗**嵌在正文句子里，硬性的坑用一句话 ⚠️ callout（纯 markdown 用 `> ⚠️` 引用）
- 控制台 / UI 上的名词用「」：「开发机」「自定义镜像」「火山镜像仓库」
- 专有名词保留英文原文，中英文之间加空格：使用 TOS 资源、打成 linux/amd64 的镜像
- 谁负责什么直接写到人：「账号与资源开通请联系 @xxx」（飞书用 @提及，markdown 写名字）

## 截图

控制台 / UI 操作用截图表达，正文只说这一步在做什么，把「点击 → 选择 → 填写」的步骤文字留给图。写作时插入占位让用户补图：`![截图：创建任务页，镜像类型选「自定义镜像」]`；两张对比图注明并排。
